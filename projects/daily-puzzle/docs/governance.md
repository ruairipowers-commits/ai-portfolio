# Governance mapping — daily-puzzle

Maps every control in the portfolio's [AI governance standard]({{SITE_URL}}/blog/governance/) (copy in [`governance/controls.md`](../governance/controls.md) when published)
to this project. **Status**: ✅ implemented · 🟡 partial / manual · ⚪ not applicable · 🔷 option documented, not built.

**Risk tier: Medium** (HITL-01). A public app that stores email addresses, emails real people every day, shows them
on a public leaderboard, publishes AI-written content and runs model-written code. No money, advice or trading.
Publishing is automatic only when independent verification passes; everything else goes to a named human.

## Model migration runbook (MODEL-02/03)

1. Add the new model to `config/models.yaml` with pricing and `approved: true` (after provider review).
2. Point `puzzle-candidate` at it.
3. Solver: `puzzle eval --role solver --alias puzzle-candidate` — must reject every broken golden draft and publish
   every good one. Generator: `puzzle eval --role generator --alias puzzle-candidate` — fresh puzzles must pass the
   verifier first time at the configured rate, with learning fields.
4. Read the report in `output/evals/` (failed cases and reasons, cost).
5. `puzzle promote puzzle-solver <model>` (or `puzzle-generator`); keep the generator and solver different models.
6. Watch a week of escalations in the review queue before trusting the new model unattended.
