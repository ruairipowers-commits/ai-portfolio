How it works

  1. A workflow reports an event whose guardrail flags match a rule (or a periodic check trips: budget, spend anomaly, unregistered workflow).
  2. The console opens an incident — one per workflow and rule until resolved, so repeats don't re-alert.
  3. At or above the auto-shutdown level it turns the workflow's kill switch off; the app refuses runs within 15 s.
  4. At or above the notify level it emails the recipients with the details and a link to the incident.
  5. You investigate, record root cause, fix and documentation, re-confirm the control and switch the workflow back on.

Limits: {{ esc.limits.emails_per_day }} emails a day across all workflows; checks every {{ esc.limits.check_interval_minutes }} minutes. {% if demo %}Public demo: an automatic switch-off lapses after {{ esc.limits.demo_shutdown_minutes }} minutes.{% endif %}
