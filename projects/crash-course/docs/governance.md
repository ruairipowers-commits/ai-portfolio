# Governance mapping — crash-course

Maps every control in the portfolio's [AI governance standard]({{SITE_URL}}/blog/governance/) (copy in [`governance/controls.md`](../governance/controls.md) when published)
to this project. **Status**: ✅ implemented · 🟡 partial / manual · ⚪ not applicable · 🔷 option documented, not built.

**Risk tier: Medium** (HITL-01). Members of the public type into it (topic suggestions, feedback), so the input can be
abusive, explicit or an injection attempt; it publishes teaching content people will rely on, so factual errors
matter; and it stores learners' email addresses and progress. No money and no advice. The controls follow from that:
every new topic, every published level and every content change needs the owner's approval; answer keys never leave
the server; and no model sits on any path a learner touches.

| HITL-02 Human approval | ✅ | Nothing reaches learners without the owner. A suggestion only becomes a course on the owner's approval. A topic flagged in a reject category (explicit, harassment, injection and so on) can't be approved at all: there's no button, no link, and the code refuses (tested), so a misclick can't publish it. ## Model migration runbook (MODEL-02/03)

1. Add the model to `config/models.yaml` with pricing (0.0 for a local Ollama model) and `approved: true`.
2. For the moderator: `course eval --alias <model>` must pass, especially must-reject recall 1.00. Then
   `course promote course-moderator <model>`.
3. For the writer: point `course-candidate` at it, draft a few levels with `COURSE_WRITER_MODEL=<model> course build
   <course> beginner`, and read them in the owner preview. Every check must pass, and spot-check the facts. Then
   `course promote course-writer <model>`.
4. Keep the old model as `course-fallback` for one cycle, then retire it.
